    Unit Name & Symbols Mapping API

    UDUNITS-2 Documentation Unit Name & Symbols Mapping API

    Functions for managing mappings between units and their names or symbols. Mappings are stored within the unit system and affect how units are parsed, formatted, and displayed.

    Functions

    Function Description
    ut_add_name_prefix() Registers a textual prefix in a ut_system for constructing derived unit names associated with compatible ut_unit objects
    ut_add_symbol_prefix() Registers a symbolic prefix in a ut_system for constructing derived unit symbols associated with compatible ut_unit objects
    ut_map_name_to_unit() Associates a textual name with a ut_unit within a ut_system, enabling lookup of units by canonical name
    ut_map_symbol_to_unit() Associates a symbolic abbreviation with a ut_unit within a ut_system, enabling lookup of units by symbol
    ut_map_unit_to_name() Defines or overrides the canonical name associated with a ut_unit in a ut_system
    ut_map_unit_to_symbol() Defines or overrides the symbol associated with a ut_unit in a ut_system
    ut_unmap_name_to_unit() Removes an existing name-to-ut_unit association from a ut_system mapping
    ut_unmap_symbol_to_unit() Removes an existing symbol-to-ut_unit association from a ut_system mapping
    ut_unmap_unit_to_name() Removes the canonical name associated with a ut_unit in a ut_system
    ut_unmap_unit_to_symbol() Removes the symbol associated with a ut_unit in a ut_system

    Usage Patterns

    The Unit Name & Symbols Mapping API operates as a progression from
    ut_system → mapping definitions for ut_unit identifiers → prefix registration rules → updated parsing and formatting behavior, enabling customization of how ut_unit objects are recognized, resolved, and represented within a unit system.

    1. Obtain ut_system

      Operations begin with an existing or newly created ut_system that will store name and symbol mappings associated with ut_unit objects.

      Typical entry points include:

      • ut_read_xml() loads a unit system definition into a ut_system
      • ut_new_system() creates an empty ut_system

      The ut_system acts as the container for all identifier mappings and prefix definitions applied to ut_unit objects.

    2. Define or override mappings

      Custom identifiers can be associated with ut_unit objects to support domain-specific terminology, abbreviations, or legacy naming conventions within a ut_system.

      • ut_map_name_to_unit() associates a textual name with a ut_unit in a ut_system
      • ut_map_symbol_to_unit() associates a symbol with a ut_unit in a ut_system
      • ut_map_unit_to_name() defines the preferred canonical name for a ut_unit
      • ut_map_unit_to_symbol() defines the preferred symbol for a ut_unit

      These mappings influence how unit expressions are interpreted and how ut_unit objects are represented as strings.

    3. Remove or modify existing mappings (optional)

      Existing identifier mappings within a ut_system can be removed or replaced when adapting terminology or resolving conflicts between unit names or symbols.

      • ut_unmap_name_to_unit() removes a name-to-ut_unit association from a ut_system
      • ut_unmap_symbol_to_unit() removes a symbol-to-ut_unit association from a ut_system
      • ut_unmap_unit_to_name() removes the canonical name associated with a ut_unit
      • ut_unmap_unit_to_symbol() removes the symbol associated with a ut_unit

      This allows applications to override default definitions or eliminate ambiguous representations within the unit system.

    4. Define prefix rules

      Prefix definitions extend the ut_system with scalable naming and symbol construction rules that apply to compatible ut_unit objects.

      • ut_add_name_prefix() registers a textual prefix used when forming derived unit names
      • ut_add_symbol_prefix() registers a symbolic prefix used when forming derived unit symbols

      Prefix rules support consistent generation of related identifiers such as kilo-, milli-, micro-, or domain-specific naming conventions.

    5. Use updated mappings in parsing and formatting

      Once mappings and prefixes are defined, they influence how unit expressions are interpreted within the ut_system and how ut_unit objects are represented.

      • ut_parse() resolves mapped names and symbols to produce a ut_unit
      • ut_format() generates string representations using mapped identifiers associated with a ut_unit

      These mappings ensure consistent terminology across parsing, formatting, and workflows that may subsequently create cv_converter objects for transformations between compatible units.
